# Issue #69 — HA, tenant isolation and disaster-recovery core

- Added `nexusq-ha` with a persistent tenant catalog, tenant-scoped durable hash-chain journals, majority-prepare/commit coordination, leader lease/fencing checks, verified snapshots/restore, and RPO/RTO objective checks.
- Each replica mutation is tenant-bound and term-bound. Prepared records are never exposed as committed state. Unresolved transactions block further local writes until reconciled.
- Recovery snapshots preserve monotonic sequence gaps and are checked against the tenant ID and every record hash before restore.
- RPO/RTO targets are bounded to one hour/four hours. Per-tenant request quotas are independent.
- **Integration boundary:** this commit provides the HA core and peer contract, not a complete network cluster. A deployment still needs a consensus-backed lease provider and authenticated peer transport, and must connect certificate issuance, revocation, serial/CRL allocation and tenant routing to the same durable transaction path. The existing `EnrollmentAuthority` and `OcspService` still use in-memory state and are not made highly available by adding this crate alone. No production HA/RPO/RTO claim is valid until that runtime integration and a failure-injection test are complete.

Runtime integration now includes `nexusq-pki-cluster`: tenant-routed enrollment/OCSP/CRL endpoints, tenant-specific bearer authentication for enrollment, public OCSP/CRL routes with per-tenant quotas, CA fingerprint consistency checks, and lease renewal shared across the tenant's CA and OCSP services. The enrollment and OCSP services can replay their committed mutations from the same tenant journal on restart. `HttpReplicaPeer` and `ReplicaNode` provide HTTPS peer replication with client identity, per-peer bearer tokens, leader allowlists and prepare/commit/abort routes. The lease provider/consensus system and TLS reverse-proxy configuration remain deployment responsibilities; tests validate the core and receiver auth, but do not simulate a live multi-host partition.
