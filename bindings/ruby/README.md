# NEXUS-Q Ruby SDK

Ruby bindings for NEXUS-Q. A thin wrapper over
[nexusq-core](../../crates/nexusq-core) generated with
[UniFFI](https://mozilla.github.io/uniffi-rs/). Every call crosses
the Rust boundary; nothing is reimplemented.

## Requirements

- Ruby 3.0 or newer.
- The `ffi` gem (`gem install ffi`).
- The Ruby crate built (`cargo build -p nexusq-ruby`).
- The directory holding `libnexusq_ruby.so` in `LD_LIBRARY_PATH` at
  runtime.

## Usage

```ruby
require 'rubygems'
require 'ffi'

$LOAD_PATH.unshift(File.expand_path('path/to/bindings/ruby', __dir__))
require 'nexusq'

vault = Nexusq::Vault.new_from_path('my.nqv', 'password', 'my-label')
puts "vault created at #{vault.path}"
puts "format version: #{vault.format_version}"
```

Run with:

```bash
LD_LIBRARY_PATH=/path/to/nexusq/target/debug ruby your_program.rb
```

The binding lives in `nexusq.rb` at the root of this directory. It
was generated by UniFFI and is not meant to be edited by hand.
Regenerate it after changing `crates/nexusq-ruby/src/nexusq.udl`:

```bash
cargo build -p nexusq-ruby
cargo run -p nexusq-ruby --bin uniffi-bindgen -- generate \
    --library target/debug/libnexusq_ruby.so \
    --language ruby --out-dir bindings/ruby
```

## What is available

- `Nexusq.version` - returns the library version.
- `Nexusq::Vault`:
  - `Nexusq::Vault.new_from_path(path, password, label)` - creates
    a new vault. `label` is optional and can be `nil`.
  - `vault.path` - returns the vault file path.
  - `vault.format_version` - returns the format version.

More operations land as the Rust API grows.

## Testing

The smoke test lives at examples/smoke/smoke.rb. Run it from the
repository root:

```bash
LD_LIBRARY_PATH=target/debug ruby bindings/ruby/examples/smoke/smoke.rb
```

Expected output:

```
ok - vault file exists on disk
ok - vault.path matches input path
ok - format_version is 1
smoke test passed
```

## Note on RubyGems

Ruby 4.x does not load RubyGems automatically. The binding itself
calls `require 'ffi'`, which needs RubyGems loaded first. Programs
that embed this binding must call `require 'rubygems'` before
`require 'nexusq'`.
