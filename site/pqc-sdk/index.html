One cryptographic core. Multiple languages.

NEXUS-Q is built around a Rust cryptographic core, with language integrations intended to let application developers call the engine from their existing stacks. Package availability and native runtime requirements vary by ecosystem and release.

Open-Source PQC SDKs for Developers

Rust

Rust is the primary implementation language. The project publishes crates including nexusq, nexusq-core, nexusq-ml-kem and nexusq-ml-dsa. Review each crate page and the release notes to choose the right API and version.

Python

The project lists a Python package named nexusq. The referenced 4.1.2 release is published as a source distribution only; no wheel is listed there. Installation may therefore require a compatible build environment and the native NEXUS-Q library. Check the current PyPI files and installation guide before assuming a one-command install will work on your platform.

TypeScript and Node.js

The project lists a nexusq npm package. Its binding uses the native library through FFI, so verify the matching native runtime, operating-system support and package version in the release documentation.

Java, Kotlin and .NET

The project lists Maven artifacts for Java and Kotlin and a NuGet package for .NET. Check the package-specific runtime assets and supported target frameworks.

Go, Swift, Dart, PHP and Ruby

Additional bindings are documented for these ecosystems. Their publication status, installation steps and platform support are not necessarily identical. Follow the matching binding README and release notes rather than assuming every package has the same maturity or requirements.

Security and production use

A language binding is an interface to the core, not an independent cryptographic implementation or a security certification. Review the threat model, release evidence and limitations. NEXUS-Q does not claim an independent third-party security audit or FIPS 140-3 validation.
